# Deploying the Academy Vision redesign (handoff)

DOCS role, 2026-10-09. Written from the files as they stood in the final tree: `dist/` = `41df3b61771c9c4e…`, 1,067
files, the same as `tmp/qa/snapshot-fixed/`. The check numbers quoted here come from `docs/BUILD-NOTES.md` §6, which
lists each command.

## 1. What to deploy

Upload the **contents** of `dist/`, not the folder itself, to the web root of `https://www.academyvisionnj.com/`. The
site is fully static, and no server code runs.

| property | what the host must do |
|---|---|
| **Directory-style paths** | Every page is `<path>/index.html` (54 pages, e.g. `dist/services/dry-eye-treatment/index.html` for `/services/dry-eye-treatment/`), plus `dist/404.html`. The host must serve `index.html` for a directory request. It should also send `/path` to `/path/`, which most static hosts do by default. The redirect files already list both forms of every moved URL. |
| **Relative links** | The build writes every page's links, images and CSS URLs relative to the page. The pages therefore work at the domain root and also under a subpath. |
| **`404.html` must sit at the domain root** | Its URLs are root-relative (`/assets/…`), because a host serves the 404 page at whatever path failed. It renders correctly only when the site is at the domain root. |
| **The live origin is built in** | The canonical tags, `og:url`, the JSON-LD `@id` and URLs, `sitemap.xml` and the `Sitemap:` line in `robots.txt` all name `https://www.academyvisionnj.com`. Deploy the site at that origin. Any other host (staging, review) needs a `noindex` copy: `node tools/make-preview.mjs --out <folder>` makes one. |
| **Indexing** | `robots.txt` reads `User-agent: *` / `Allow: /` plus the Sitemap line. `sitemap.xml` lists the 54 pages with no `lastmod`. `404.html` carries `<meta name="robots" content="noindex">`. The home page keeps the source's Google and Bing site-verification tokens. |
| **Caching** | Assets have fingerprinted names (`name.<10 hex>.ext`; all 1,008 asset names match, BUILD-NOTES 5.1 CSP-12), so they can be cached for a year. HTML should not be cached long. On Apache, `dist/.htaccess` sets the one-year rule for fingerprinted files and leaves HTML to the server's default. `dist/` has no Netlify `_headers` file, so on Netlify the host's default caching applies. |

### 2.1 By host

- **Netlify:** `dist/_redirects` has 48 lines of the form `/old /new/ 301`. Netlify reads the file from the publish
  folder. Per Netlify's own documentation, a `404.html` at the root is served for misses; that behaviour was not tested
  here.
- **Apache:** `dist/.htaccess` needs `AllowOverride` to permit it. It contains:
  - `ErrorDocument 404 /404.html`;
  - 24 rules `RedirectMatch 301 ^/old/?$ /new/` inside `<IfModule mod_alias.c>`. `RedirectMatch` anchors both ends. A
    plain `Redirect` would also prefix-match deeper paths.
  - `mod_deflate` compression and, through `mod_headers`, `Cache-Control: public, max-age=31536000, immutable` for
    fingerprinted files. Both sit inside `IfModule`, so a server without those modules ignores them.
- **Other hosts** (nginx, S3 + CloudFront and so on): translate the 24 rules into the host's own syntax, keeping 301
  and exact matching, and set its 404 page to `/404.html` (for nginx: `error_page 404 /404.html;`).
- **GitHub Pages and other hosts without server redirects** (review previews only): `node tools/make-redirect-stubs.mjs
  --out preview` writes a small meta-refresh page at each old path in the preview copy. **Never run it into `dist/`.**
  On a host that honours `_redirects`, a file at the old path would shadow the 301.

### 2.2 Test after deploying

The rules were checked only as rule tables (BUILD-NOTES §6: build-verify (d); the content reviewer simulated all 48
forms as one hop, 301, existing target). On the real host, run:

```sh
grep -v '^#' dist/_redirects | while read -r from to code; do
  printf '%s -> ' "$from"
  curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' "https://www.academyvisionnj.com$from"
done
```

Every line should read `301 https://www.academyvisionnj.com<new URL>`. Then request each target once and expect 200.
Also request a missing nested path such as `/no/such/page/`: it should answer 404 with the styled 404 page, including
its CSS and images. URLs that the 31-page crawl did not find have no rule and get the 404 page.

## 6. UNVERIFIED

- **Safari and Firefox** (A10). Only headless Chrome was tested. `backdrop-filter`, `mask-composite`, `:has()` and
  scroll timelines have coded fallbacks that never ran.
- **A real host:**
  - the 48 redirect forms (D8);
  - 404 handling at nested paths;
  - the `.htaccess` compression and caching (CSP-12);
  - Netlify's handling of `_redirects` and `404.html`.
- **Third parties:** the live Google map and the scheduler page never loaded. Analytics are absent.
- **Real-network performance.** Only localhost timings exist. They include the 536,926 B `/eye-health/` hero and the
  70-95 KB insurance logos, both deferred (OPEN-DECISIONS QA9).
- **Social previews:** `og:image` is set on 54/54 pages as a 1280 px WebP. Whether every platform accepts WebP was not
  checked (CSP-5).
- **Assistive technology:** no real screen reader was used (F10), and the HTML was not run through a validator (F11).
  The JSON-LD was not run through Google's Rich Results test.
- **Known gaps** (measured, not fixed):
  - at 320 px wide the pages are 347 px (BUILD-NOTES 4.5);
  - at 768x1024 the `/products/` glass panel covers part of the model's face (4.5);
  - with WCAG 1.4.12 text spacing at 1440 and 1600 px, the Book pill ends 12-15 px past the header bar (5.3,
    OPEN-DECISIONS QA10);
